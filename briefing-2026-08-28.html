2a. Relevance for Claude / MCP-Centered Work

Rank Agent / Platform Justification
1 Model Hardware Standard (MHS) New, August 27, and MCP is one of its three control mechanisms. MHS introduces a standardized driver with primitives as simple as "read" (get temperature) and "write" (set temperature), makes each device discoverable in a standard format, and lets a user describe machine characteristics in natural language tags — including physical facts a model cannot infer from code, such as the weight of a robot arm. The driver then generates a reference file stating what a device can measure, what can be adjusted, and what safety limits will be enforced. Control runs through MCP, the CLI, and code files (APIs), which together allow orchestration across multiple devices from a single line of code (Source: anthropic.com — primary). ✅ Integration time drops from weeks or months to hours or minutes, per Anthropic. Early adopters named: Hugging Face, adding MHS support to the LeRobot robotics library, and Raspberry Pi, enabling MHS across several products after testing a Camera MHS Driver. ⚠️ Research preview, waitlisted, not open source yet.
2 Claudeforce — Salesforce in Claude Announced August 26 and missed by this series yesterday. Salesforce in Claude is a Plugin with 37 prebuilt sales skills — meeting prep, deal health review, pipeline review — built jointly and engineered against Claude's reasoning, agentic tool use and generative UI rather than wrapped around a generic API. It runs on AIforce, Salesforce's harness exposing business data and workflows through MCP servers, APIs and CLI tools (Source: Salesforce newsroom, August 26, 2026 — primary). ✅ Governance is the notable part: actions route back through Salesforce so business rules are enforced, an admin connects it once with authentication and permissions managed centrally, and every seller gets access with no per-user setup and no new permissions model. Divergence analysis. The three lenses agree more than usual, and where they disagree the disagreement is informative. MHS ranks first on relevance and last on maturity — the widest spread in this table's recent history, and the correct reading is that a specification with named launch partners and a published limitations list is strategically significant and operationally premature at the same time. Claudeforce ranks first on momentum and second on both other lenses, which is unusual: distribution events normally score high on buzz and low on readiness, but the Bedrock-inside-the-Trust-Boundary path gives this one a genuine deployment story. Claude Code is the only entry in the top three of all three lenses, which is what a mature product looks like. And MCP appears on two lenses without having published anything in six days — it scores on being the substrate other people's announcements are built on, which is a stronger position than shipping.

What This Means for You. Two of today's three top-ranked items are governance surfaces wearing product clothing, and that is the practical observation of the week. --restricted is a containment mode a security team can specify in a written policy by name. Salesforce in Claude routes every action back through Salesforce so business rules are enforced, with one admin connection and centrally managed permissions — which is, in effect, an answer to the question every agent rollout eventually reaches: who decides what the agent is allowed to do, and where is that decision written down? The answer is increasingly "in a system that already exists," and that is a better answer than the ones available in June. The caution is MHS, and it is a caution about scope, not safety. An organization reading "AI agents can now operate laboratory equipment" will hear a capability claim; the accurate framing is that a waitlisted research preview reduced integration time for organizations that already had the instruments, the drivers and the expertise. The transferable lesson for anyone training staff on agentic tools is the one Anthropic printed against its own product: the model learned the physical world through text and images, so its physical reasoning has limits that require expert oversight. That sentence generalises to almost every agentic deployment an organization will attempt this year.

What This Means for You. The MHS release quietly changes what a documented AI implementation policy has to cover, and most policies written this year do not cover it. Nearly every such policy assumes the agent's blast radius is data — files read, records updated, messages sent. MHS extends the blast radius to matter: a liquid handler that dispenses, an arm that lifts, a laser that calibrates. Anthropic anticipated this and built the answer into the driver — the auto-generated reference file states what safety limits will be enforced, which is the first time this series has seen a machine-readable safety boundary shipped as part of an integration standard. That is a template worth borrowing even for organizations that will never touch a microscope: a policy is more enforceable when the limits live in the interface than when they live in a PDF. The second, more immediate item is --restricted. It is a single flag that produces a defensible answer to the question an audit committee actually asks — what can this thing do if it goes wrong? — and it belongs in the standard configuration section of any agent deployment document from this week forward. The third item is a caution about the Jalapeño figures, which will circulate widely and are, today, an unread secondary source. This briefing prints them as reported and would not put them in a board deck.
